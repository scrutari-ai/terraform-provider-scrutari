# Publishing to the Terraform Registry

How to publish `terraform-provider-scrutari` so customers can consume it
as `source = "scrutari-ai/scrutari"`. This is a one-time setup, then a
tag push per release.

The repo is already prepared: `.goreleaser.yml` builds and GPG-signs the
release artifacts, `terraform-registry-manifest.json` declares protocol
6.0, `docs/` is generated by `tfplugindocs`, the README and LICENSE are
in place. What remains is the GPG key, the secrets, the first tag, and
connecting the repo on the Registry.

## One-time prerequisites

1. The GitHub repository must be PUBLIC, named
   `terraform-provider-scrutari`, owned by the `scrutari-ai`
   organization. The Registry namespace (`scrutari-ai`) must match the
   GitHub org that owns the repo.

2. Generate a dedicated release GPG keypair (do not reuse a personal
   key). The full procedure is documented in the header of
   `.github/workflows/release.yml`. In short:

   ```sh
   gpg --full-generate-key            # RSA 4096, no expiry
   gpg --list-secret-keys --keyid-format long   # note the FINGERPRINT
   gpg --armor --export-secret-keys <FINGERPRINT> > priv.asc
   gpg --armor --export <FINGERPRINT> > pub.asc
   ```

3. Add three repository secrets (Settings, Secrets and variables,
   Actions):

   - `GPG_PRIVATE_KEY`: the contents of `priv.asc`
   - `PASSPHRASE`: the passphrase set during key generation
   - `GPG_FINGERPRINT`: the long fingerprint string

   Keep `priv.asc` and the passphrase in your password manager. Delete
   the local `priv.asc` after pasting it into the secret.

## First publish

1. Cut the first release tag and push it. GoReleaser fires on `v*`:

   ```sh
   git tag v0.1.0
   git push origin v0.1.0
   ```

   The release workflow cross-compiles the binaries, writes
   `terraform-provider-scrutari_0.1.0_SHA256SUMS`, GPG-signs it to
   `..._SHA256SUMS.sig`, and creates the GitHub Release with all assets
   attached. Confirm the Release shows the binaries plus the SHA256SUMS
   and its `.sig`.

2. On https://registry.terraform.io, sign in with GitHub, then Publish,
   then Provider. Authorize the Terraform Registry GitHub app for the
   `scrutari-ai` org and select the `terraform-provider-scrutari` repo.

3. Upload the GPG PUBLIC key: paste the contents of `pub.asc` into the
   namespace's GPG keys in the Registry settings. The fingerprint must
   match `GPG_FINGERPRINT`, or ingestion fails signature verification.

4. The Registry ingests the `v0.1.0` tag, verifies the signature against
   the uploaded public key, and indexes the provider. It appears at
   `https://registry.terraform.io/providers/scrutari-ai/scrutari`, and
   customers can use `source = "scrutari-ai/scrutari"`.

## Subsequent releases

Just push a new semver tag:

```sh
git tag v0.2.0
git push origin v0.2.0
```

GoReleaser builds and signs; the Registry picks up the new version
automatically (the GitHub app webhook). No Registry UI step is needed
after the first publish.

## Pre-publish checklist

- `go build ./...` is clean and `make docs` is up to date (the Registry
  renders `docs/` on the provider page).
- The version in any docs examples uses a `~>` constraint that allows
  the tag being published.
- The acceptance suite has been run manually at least once against the
  live gateway and is green (it does not gate the release, but a broken
  resource should not ship).
- `terraform-registry-manifest.json` protocol version matches the
  plugin-framework version the provider builds against (6.0 today).

## Versioning note

While the provider is pre-1.0 (`0.x`), treat every release as
potentially breaking and pin with `~> 0.1` in examples. Move to `1.0.0`
only when the resource schemas are stable enough to promise backward
compatibility under semver.
